## GAP-001 — 진행 중 결석을 수강 종료·탈퇴 뒤 복원

- 상태: **정상 정책 확정 / 검토 완료**. 관련: ATT-003, STU-005.
- 사용자 결정: 현재 흐름은 허용 가능한 정상 동작이다. 수강생 상태는 이용 상태, 출결은 해당 회차의 참석 사실로 구분하며 출결 정정에 수강 중 복귀를 요구하지 않는다.
- 현재: 결석 취소된 진행 중 회차는 유효 진행 수업 집계에서 제외되어 종료·탈퇴가 가능하다. 관리자가 출석으로 정정하면 정원·학생 중복 검사 후 해당 예약의 취소 상태를 해제한다.
- 보존: 학생은 종료·탈퇴 상태를 유지한다. 상태 변경 때 취소한 다른 예정 예약은 복구하지 않으며 기존 출결 변경 이력을 보존한다.
- 근거: `sql/checks/booking-lifecycle.mjs`의 클래스 3상태 × 종료·탈퇴 2상태 조합. 이전 policyQuestion 분류 6건을 사용자 결정에 따라 정상 검증으로 바꾼다. 실제 고객 예약 6건을 뜻하지 않는다.
- 처리: 제품 로직은 수정하지 않고 ATT-003의 현재 계약을 명확히 한다.

## GAP-002 — 복수 조직 소속 계정의 분리 동작

- 상태: **조직별 전화번호 고유 범위 확인 / 복수 조직 문제 확인 항목**. 관련: STU-006, SEC-001, AUTH-003, BOOK-001.
- 확인: 전화번호는 전역 고유 키가 아니다. `organization_members`의 조직 ID + 정규화 전화번호(`student_phone`) 조합으로 중복을 제한하므로 다른 조직에는 같은 번호가 존재할 수 있다. 전화번호 일치만으로 계정을 자동 연결하지 않는다.
- 남은 문제: 조직 멤버십의 상태는 분리되어 있지만 DELETED 처리는 프로필의 계정 접근을 전역 차단한다. 하나의 계정이 두 조직에 포함된 경우 한 조직 탈퇴가 다른 조직 이용에 영향을 줄 수 있다.
- 관련 확인 사항: 기존 계정의 다른 학생 프로필 초대 수락은 `account_already_in_use`로 막힌다. 인증 후 소속 조직 조회·선택과 홈/예약/학습 기록의 선택 범위를 함께 확인해야 한다. 일반 로그인 전에는 사용자를 식별할 수 없다.
- 공통 필드 제한: 수강 시작·종료일은 프로필 공용이며 복수 조직 변경에는 `course_period_shared_profile` 제한이 있다. 조직별 수강 기간까지 분리된 것으로 기록하지 않는다.
- 근거: `app/features/organizations/schema.ts`, `sql/migrations/0018_student_management_integrity.sql`, `sql/migrations/0024_student_lifecycle.sql`, `sql/migrations/0016_tenant_security_and_schedule_stats.sql`, `app/features/schedules/utils/student-calendar.server.ts`.
- 처리: 현재 문제 확인 항목으로 보존한다. 복수 조직 개선·고유 제약 변경·계정 병합·데이터 이동은 이번 검토에서 구현하지 않는다.

## GAP-003 — 수강생별 클래스 배정 없음

- 상태: **현재 미지원 유지 / 검토 완료**. 관련: BOOK-001.
- 현재: 같은 조직의 NORMAL STUDENT는 ACTIVE 클래스를 선택한다. 별도 학생-클래스 수강 배정/계약 테이블이 없다.
- 근거: `getStudentBookingOrganization`, 최종 `guard_schedule_write`, `docs/booking-state-audit-2026-10-30.md`.
- 특정 반 학생만 해당 클래스를 예약해야 한다면 별도 요구사항·모델·권한 검증이 필요하다.

## GAP-004 — 총 회차와 회차 소진

- 현재: `total_sessions`는 소개 정보다. 관리자 반복 생성은 학생 수강 종료일까지이며 회차권 잔여·차감·환급·유료 수강 계약은 구현된 기능으로 보지 않는다.

## GAP-005 — 상담 CTA와 중단 API

- 상태: **후속 정리 보류 / 소스상 화면·기능 상태 불일치**. 관련: PUB-001.
- 현재: 공개 클래스 화면에 상담 입력·제출 코드가 남아 있지만 API는 정책상 항상 503이다. 실제 상담 저장·전송을 재활성화하지 않았다.

## GAP-006 — 관리자 조직 선택

- 상태: **후속 정리 보류 / 현재 제한**. 관련: SEC-001, SER-004.
- 현재: 공통 관리자 guard는 명시 조직 인자가 없으면 첫 NORMAL ADMIN 멤버십을 사용한다. 테스트 발송은 `.single()` 멤버십 조회로 여러 관리자 조직을 다루지 못할 수 있다.
- 근거: `app/features/admin/guards.server.ts`, `app/features/notifications/api/test-send.tsx`.
- 학생 예약의 조직 선택 수정이 관리자 전체의 복수 조직 전환 지원 완료를 의미하지 않는다.

## GAP-007 — 테스트 발송의 서비스 관리자 판정 불일치

- 상태: **후속 정리 보류 / 소스상 불일치 / 재현·수정 필요**. 관련: SEC-001, NOT-006.
- 공통 서비스 관리자 guard는 현재 Auth의 `app_metadata.role === "super_admin"`을 사용한다. 테스트 발송 API는 `is_super_admin === true` 또는 `role === "SUPER_ADMIN"`을 따로 읽는다.
- 근거: `app/features/admin/guards.server.ts`, `app/core/lib/privileged-auth.server.ts`, `app/features/notifications/api/test-send.tsx`.
- 공통 계약에 맞는 실제 재현·회귀가 필요하다. 이 차이를 별도 정상 권한 정책으로 승인하거나 수정하지 않았다. 실제 발송으로 재현하지 않는다.

## GAP-008 — 테스트 발송 일일 한도와 시간대

- 상태: **후속 정리 보류 / 검증·일관성 공백**. 관련: NOT-006.
- 일반 관리자는 본인 번호·조직/프로필별 5회 제한을 검사한다. 날짜 범위는 서버 로컬 `setHours`이고 count 조회·발송 생성·로그가 별도 단계다. 로그 저장 오류도 응답에서 따로 처리하지 않는다.
- 근거: `app/features/notifications/api/test-send.tsx`의 DAILY_TEST_LIMIT 및 test_send_logs 처리.
- KST 자정과 병렬 요청에서 한도가 유지되는지 재현하고 원자적인 제한이 필요한지 정리해야 한다. 현재 구현이 모든 경합에서 정확히 5회를 보장한다고 주장하지 않는다.

## GAP-009 — 관리자 가입과 문의의 전용 회귀

- 상태: **후속 정리 보류 / 자동 검증 연결 부족**. 관련: AUTH-002, PUB-002.
- 관리자 조직 설정은 여러 쓰기와 보상 삭제를 사용하며 단일 트랜잭션이 아니다. 중간 실패·보상 실패·중복 동시 제출 검증이 필요하다.
- 일반 문의의 두 CAPTCHA·발송 실패·법적 slug 허용 목록은 코드를 검토했으나 전용 자동 회귀 연결이 부족하다.
- 기존 E2E 파일의 존재를 이번 실행 통과로 기록하지 않는다. `policy-map.json`의 source-reviewed를 확인한다.

## GAP-010 — 메일 큐의 실패 복구

- 상태: **후속 정리 보류 / 신뢰성 검토 필요**. 관련: NOT-003, NOT-007.
- 예약 알림 메일에는 멱등 키와 전달 가능 재검사가 있다. 별도의 가입 환영 메일 worker는 PGMQ pop 후 발송 오류를 기록하고 200을 반환한다.
- 근거: `app/features/cron/api/mailer.tsx`. 큐 pop·발송 사이 장애의 재처리 보장은 별도 검증이 필요하다. 서로 다른 두 메일 경로를 같은 보장으로 설명하지 않는다.

## GAP-011 — 실제 환경 통합 검증 범위

- 상태: **후속 정리 보류 / 검증 한계**. 관련: PLAT-003, BOOK-005, NOT-005.
- PGlite는 auth·cron·pgmq를 fixture로 대체한다. 실제 두 DB 연결의 경합, PostgREST 관계 추론/캐시, pg_cron·pg_net, OAuth 제공자, 기기 푸시·메일 전달까지 증명하지 않는다.
- 과거 `sql/operations/*.result.json`은 과거 실행 증거다. 이번 기준 전체에서 실제 통합 검증을 새로 실행했다는 뜻이 아니다.
- 이번에는 고객 DB 접속·시험 데이터·발송·운영 배포를 하지 않는다.

## GAP-012 — 원격 필수 체크 설정

- 상태: **후속 정리 보류 / 원격 설정 미변경**. 관련: SPEC-003.
- 저장소에 CI를 추가했으나 원격 branch protection/ruleset의 required status는 변경하지 않았다. 원격에서 실행된 CI 결과도 아직 없다.
- 사용자 요청으로 원격 반영할 때 `policy-and-regression` 체크를 필수로 둘지 확인한다.

## GAP-013 — 계정 삭제와 기록 보유

- 상태: **후속 정리 보류 / 제품·데이터 보유 정책 점검 필요**. 관련: AUTH-005, STU-005.
- 실제 인증 계정 삭제 API와 관리자 멤버십 탈퇴는 서로 다른 경로다. 계정 삭제의 FK/cascade 및 개인정보 처리 문서와 수업 이력 보존의 정합성을 별도 검토한다.
- 이번 작업에서 삭제 경로를 호출하거나 데이터 보유 정책을 변경하지 않았다.
