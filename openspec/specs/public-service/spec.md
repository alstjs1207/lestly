# public-service Specification

## Purpose

공개 클래스 상담 접수의 보안 경계, 조직별 상담관리와 기존 이력 보존, 별도 문의 폼과 법적 페이지를 정의한다. 설정과 저장 검증을 통과한 상담만 접수한다.

## Requirements

### Requirement: PUB-001 공개 상담 접수와 남용 방지

시스템 SHALL 공개 ACTIVE 클래스에만 비회원 상담을 허용하고 이름·정규화 전화·최대 2,000자 문의를 검증한다. 메서드·동일 출처·본문 크기·공유 요청 제한을 검사하고 같은 신청의 재시도는 중복 저장하지 않는다. 조직은 클래스에서 결정하며 계정·수강생을 생성하지 않는다. 보안 설정/저장 실패는 접수 성공으로 표시하지 않는다.

#### Scenario: 유효한 상담 제출

- **WHEN** 외부 사용자가 공개 ACTIVE 클래스에 정상 상담 정보를 POST한다
- **THEN** 해당 조직 상담을 저장하고 계정 생성·알림톡·메일 발송 없이 성공을 응답한다.

#### Scenario: 비공개 또는 비활성 클래스

- **WHEN** 신청자가 존재하지 않거나 비공개·DRAFT·ARCHIVED 클래스 ID 또는 다른 조직 ID를 제출한다
- **THEN** 클래스가 접수 가능하지 않으면 저장을 거절하고 사용자 조직 ID는 신뢰하지 않는다.

#### Scenario: 요청 제한 설정 누락

- **WHEN** 요청 제한용 HMAC 설정이나 신뢰 IP가 없다
- **THEN** 상담과 알림을 생성하지 않고 준비 중 상태로 안내한다.

#### Scenario: CAPTCHA 없는 상담 접수

- **WHEN** CAPTCHA 키나 토큰 없이 유효한 상담 정보를 제출하고 요청 제한과 중복 검사를 통과한다
- **THEN** CAPTCHA 또는 외부 봇 확인 서비스 호출을 요구하지 않고 정상 접수한다. 입력·권한·DB 직접 접근 보호는 유지한다.

#### Scenario: 한도와 중복

- **WHEN** IP 10회/10분, 조직+연락처 3회/시간 또는 조직 100회/시간의 고정 시간창 한도에 도달하거나 같은 요청 UUID를 재제출한다
- **THEN** 한도 초과는 429와 재시도 안내를 반환하고, 24시간 내 동일한 성공 요청은 추가 상담/알림 없이 성공한다. 동일 UUID의 다른 내용은 거절한다.

### Requirement: PUB-002 일반 문의와 법적 문서

시스템 SHALL 일반 문의에서 이름·메시지와 두 CAPTCHA의 서버 검증을 요구하고 이메일은 선택으로 받는다. 검증을 통과한 문의만 운영자 메일로 보내고 실패는 성공으로 표시하지 않는다. 법적 페이지는 허용된 약관·개인정보 문서를 표시한다.

#### Scenario: CAPTCHA 검증 실패

- **WHEN** 일반 문의에서 hCaptcha 또는 Turnstile 검증 하나가 실패한다
- **THEN** 문의 발송을 하지 않고 입력 오류를 표시한다.

### Requirement: PUB-003 상담 관리와 기존 이력

시스템 SHALL NORMAL ADMIN에게 자기 조직의 상담만 별도 목록·상세로 제공하고 기존 이름·전화·문의·상태·결과·메모·완료 이력을 보존한다. 목록은 이름·전화·내용 요약을 표시하고 상세로 연결한다. 유효한 전화는 전화 연결을 제공한다. 수정은 상태·결과·최대 5,000자 메모로 제한하고 완료 기록은 처리자/시각으로 관리한다.

#### Scenario: 다른 조직 조회와 수정

- **WHEN** 조직 A 관리자 또는 학생이 조직 B의 상담 ID로 상세/수정을 요청한다
- **THEN** 상담을 노출하거나 수정하지 않으며 원본 전화·문의·조직·작성 시각 변경도 허용하지 않는다.

#### Scenario: 목록과 상세

- **WHEN** 관리자가 상담관리 목록에서 신청 건 또는 유효한 전화번호를 선택한다
- **THEN** 신청 건은 전문/처리 상세로 이동하고 전화번호는 상세 이동 없이 통화 연결을 요청한다. 알림관리 목록에는 상담 접수 건을 섞지 않는다.

#### Scenario: 완료와 대기 복귀

- **WHEN** 관리자가 상담을 완료하거나 다시 대기로 변경한다
- **THEN** 완료 시각·담당자를 기록하거나 해제하고 기존 문의 내용과 알림 읽음 상태는 유지한다.

#### Scenario: 기존 상담 보존

- **WHEN** 새 상담 기능의 DB 변경을 적용한다
- **THEN** 기존 상담/예약/프로필/발송 이력을 다시 쓰거나 삭제하지 않고 과거 상담에 새 푸시를 재생하지 않는다.
