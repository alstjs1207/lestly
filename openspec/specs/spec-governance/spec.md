# spec-governance Specification

## Purpose
AI가 현재 정책·진행 변경·검증 공백을 구분하고 필요한 문맥만 읽도록 한다. 명세와 코드·테스트의 연결, 새 파일 분류, 변경 근거와 자동 검증 결과를 유지한다.

## Requirements

### Requirement: SPEC-001 정책과 근거 추적

관리 도구 SHALL 모든 현재 요구사항의 고유 ID와 구현 근거를 확인한다. automated와 source-reviewed를 구분하고 없는 파일·중복 ID·시나리오 누락·잘못된 상태·미등록 요구사항을 실패로 보고한다. 테스트 경로 연결을 실제 통과·전체 커버리지로 표시하지 않는다.

#### Scenario: 근거 삭제

- **WHEN** 명세의 연결된 테스트 파일 또는 구현 근거가 사라진다
- **THEN** spec:check가 실패하고 해당 요구사항과 경로를 표시한다.

### Requirement: SPEC-002 소스 분류와 관련 문맥

관리 도구 SHALL 관리 대상 소스를 빠짐없이 영역에 연결하고 신규·삭제·분류 변경 시 인덱스 차이를 검출한다. domain 또는 파일 경로로 현재 명세·근거·검증 명령을 찾게 하고 기본 조회에 과거 archive 전체를 포함하지 않는다.

#### Scenario: 미분류 기능 추가

- **WHEN** 등록된 영역에 속하지 않는 새 feature 소스를 추가한다
- **THEN** 인덱스·검증에서 미분류 파일을 실패로 보고한다.

### Requirement: SPEC-003 변경과 자동 검증

개발 절차 SHALL 동작 변경 영역마다 현재 명세 변경 또는 해당 영역 요구사항 ID를 포함하는 OpenSpec change 기록을 남긴다. CI는 명세·단위·격리 DB·타입·빌드·SSR을 실행하고 실패를 성공으로 처리하지 않는다. 원격 branch protection 설정 여부는 별도 운영 상태로 명시한다.

#### Scenario: 동작만 변경

- **WHEN** PR에서 예약 동작 코드를 변경하고 관련 명세나 change 기록을 남기지 않는다
- **THEN** 변경 누락 검사가 실패한다.

#### Scenario: 기존 정책의 버그 수정

- **WHEN** 현재 요구사항을 유지하는 버그 수정에서 해당 요구사항 ID와 재현·검증을 change에 기록한다
- **THEN** 불필요한 정책 변경 없이 변경 관리 근거로 인정한다.
