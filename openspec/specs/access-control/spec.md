# access-control Specification

## Purpose
조직별 데이터 격리, 서버 권한 확인과 공개·작업자 경계를 정의한다. 화면의 숨김 여부와 관계없이 API, RPC, RLS, 저장소에서 유지해야 하는 보안 계약을 다룬다.

## Requirements

### Requirement: SEC-001 조직 역할과 서비스 관리자

시스템 SHALL 조직 멤버십의 ADMIN/STUDENT와 NORMAL/GRADUATE/DELETED를 구분한다. 조직 관리자는 해당 조직의 NORMAL ADMIN이어야 하며 서비스 전체 관리자는 현재 인증 서비스의 app_metadata.role=super_admin으로 확인한다. 별도 owner 조직 역할을 가정하지 않는다.

#### Scenario: 권한 회수

- **WHEN** 과거 토큰에 서비스 관리자 값이 있으나 현재 인증 정보에서 회수되었다
- **THEN** 과거 메타데이터만으로 서비스 관리 기능을 허용하지 않는다.

### Requirement: SEC-002 조직 간 참조와 조회 격리

시스템 SHALL 조직별 조회·변경과 학생·클래스·강사·예약 사이의 조직 일치를 검증한다. 서버 전용 권한을 쓰는 요청도 호출자의 역할과 대상 조직을 먼저 확인한다. 다른 조직의 식별자를 제출해 권한을 얻을 수 없어야 한다.

#### Scenario: 다른 조직 식별자

- **WHEN** 조직 A 관리자가 조직 B 학생·클래스·강사의 식별자로 쓰기를 시도한다
- **THEN** 변경을 거절하고 양쪽 조직의 기존 데이터를 보존한다.

### Requirement: SEC-003 브라우저 변경 요청과 리다이렉트

시스템 SHALL 브라우저 변경 요청의 허용 메서드와 동일 출처를 검사한다. 외부·형제 출처, opaque origin, 악성 리다이렉트는 거절한다. 헤더 없는 서버 클라이언트의 기존 호환성은 유지한다.

#### Scenario: 형제 사이트 요청

- **WHEN** 같은 사이트의 다른 origin이 보호된 브라우저 변경 API에 요청한다
- **THEN** 동일 출처가 아니므로 쓰기 전에 거절한다.

#### Scenario: 외부 이동 값

- **WHEN** 로그인 후 이동 값으로 //외부주소 또는 역슬래시가 제출된다
- **THEN** 안전한 내부 기본 경로를 사용한다.

### Requirement: SEC-004 작업자와 저장소 경계

시스템 SHALL 비밀 값이 없거나 일치하지 않는 작업자 요청을 거절한다. 알림톡 Edge는 구성된 작업자 비밀 값 또는 그 값이 없을 때 서비스 역할 키의 Bearer 자격을 요구한다. 업로드는 로그인 사용자와 허용 조직의 경로에 제한하고 공개 읽기를 공개 쓰기로 확대하지 않는다.

#### Scenario: 설정 없는 작업자

- **WHEN** cron 비밀 값이 설정되지 않은 환경에서 요청한다
- **THEN** 빈 인증 값과 관계없이 요청을 거절한다.
