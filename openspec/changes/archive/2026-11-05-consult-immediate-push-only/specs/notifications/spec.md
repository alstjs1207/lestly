## MODIFIED Requirements

### Requirement: NOT-005 기기별 푸시와 안전한 전달

시스템 SHALL 조직 관리자 기기 구독과 클래스 담당 강사의 연결 계정을 통해 예약 푸시를 전달한다. 임의 외부 endpoint를 거절하고 알려진 브라우저 푸시 서비스만 허용한다. 만료 구독은 정리하며 예약 푸시는 재시도·lease·claim 토큰으로 전달 상태를 관리한다. 상담은 접수 직후 기기별 한 번만 시도하고 자동 재시도·보호 우회키를 사용하지 않는다.

#### Scenario: 발송 후 상태 저장 실패

- **WHEN** 외부 푸시 서비스가 수락한 뒤 상태 저장에 실패한다
- **THEN** 기존 lease를 유지하고 즉시 재발송하지 않는다.

#### Scenario: 예약 후 즉시 푸시 실패

- **WHEN** 예약 커밋 뒤 즉시 푸시 처리에 오류가 난다
- **THEN** 이미 성공한 예약을 실패 응답으로 바꾸지 않고 재시도 대상을 유지한다.

#### Scenario: 새 상담의 기기 푸시

- **WHEN** 조직에 새 상담이 접수되고 활성 ADMIN의 허용 기기 구독이 있다
- **THEN** 해당 조직 관리자 기기에만 전화·이름·문의 전문 없는 푸시를 전달하며 클릭 시 인증된 해당 상담 상세로 이동한다. 임의 외부 URL은 열지 않는다.

#### Scenario: 상담 즉시 푸시 실패와 정기 작업 분리

- **WHEN** 상담 푸시의 네트워크/서비스 오류 또는 발송 뒤 상태 저장 실패가 발생하거나 정기 worker가 실행된다
- **THEN** 해당 상담 기기의 발송을 재시도하지 않고 정기 worker도 상담 이벤트를 가져가지 않는다. 저장된 상담과 종 아이콘 알림은 유지하고 상담 전용 재시도 job/URL은 제거한다. 기존 예약 재시도는 유지한다.

#### Scenario: 여러 기기의 즉시 발송

- **WHEN** 해당 조직의 허용 기기가 한 배치를 넘는다
- **THEN** 접수 요청에서 새 기기를 배치별로 모두 한 번씩 시도하고 이미 시도한 기기나 만료된 상담 lease를 다시 가져가지 않는다.
