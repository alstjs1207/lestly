# Proposal

## Why

수강생 등록 화면의 선택 날짜와 실제 자동 저장 동작이 달라 종료일을 의도하지 않게 1년으로 저장한다. 운영자가 기간을 명시적으로 선택하고, 수강 기간이 없는 계정은 로그인과 기존 기록 조회를 유지하면서 새 예약을 제한해야 한다.

## What Changes

- 시작일·종료일의 `(선택)` 표시는 유지하고 종료일 아래 1개월·3개월·6개월·1년 버튼을 제공한다. 시작일 기준 달력 월을 더하고 대상 월의 말일로 보정한다.
- 신규 시작일 미입력은 KST 오늘로 저장한다. 종료일 자동 생성은 제거하고 직접 입력 또는 버튼 선택을 요구한다. 사용자 확인: 시작일을 비워도 신규 등록에는 종료일이 필수다.
- 시작일이 있는 수정 요청에도 종료일을 요구한다. 날짜 없는 기존 프로필의 로그인·조회와 예약·출결 이력은 유지한다.
- **BREAKING**: 신규 단건·일괄 등록은 명시적 종료일을 요구하며, 기간이 불완전한 학생의 새 예약·일정 변경을 화면·API·DB에서 차단한다. 기존 예약의 취소·출결 처리는 유지한다.

## Capabilities

### New Capabilities

없음.

### Modified Capabilities

- `student-management`: STU-002·STU-004의 일괄 기간 입력, 종료일 명시, 기간 버튼과 미등록 규칙.
- `booking`: BOOK-001의 불완전한 수강 기간 예약 차단.
- `recurring-schedules`: SER-004의 관리자 등록·변경에도 동일한 기간 등록 검사.

## Impact

SPEC-002·SPEC-003의 기존 소스 분류/변경 근거 절차에 따라 새 파일을 등록한다. PLAT-003의 마이그레이션 실행 메타데이터인 `_journal.json`의 누락된 platform 분류도 보완하며 새 SQL의 명시적 정책 분류 검사는 유지한다. 수강생 단건·일괄 폼과 저장 helper, 예약 loader/API·날짜 안내, 신규 SQL migration, 단위·PGlite·SSR 검사와 policy-map/source-index를 변경한다. 기존 데이터의 날짜를 채우거나 예약을 삭제하지 않는다. 로그인·초대 정책은 바꾸지 않으며 DB 적용·배포·커밋·푸시는 이번 요청에 포함하지 않는다.

수강생 일정 화면의 기간 미등록 안내는 LEARN-001·LEARN-002의 출석 기반 집계와 기존 일정 조회를 유지한다. 기존 학습 집계 정책은 변경하지 않으며 화면과 loader 회귀로 예약 차단 이후에도 기록이 표시됨을 확인했다.
