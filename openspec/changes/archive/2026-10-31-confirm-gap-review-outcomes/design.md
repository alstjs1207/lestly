# Design

## Context

GAP-001의 6개 조합은 이미 실제 격리 SQL 회귀에서 복원과 학생 상태 유지를 검사한다. 제품 동작은 그대로 두고 미확정이었던 해석을 사용자 결정에 맞춘다.

## Goals / Non-Goals

**Goals:** 현재 명세와 검토 목록, 회귀 결과의 의미를 일치시킨다.

**Non-Goals:** 새로운 로그인·조직 선택·초대 연결·메일 기능을 구현하거나 운영 DB에 적용하지 않는다.

## Decisions

- ATT-003의 기존 시나리오를 모두 유지하고 종료·탈퇴 후 진행 중 결석을 출석으로 정정하는 시나리오를 추가한다.
- 기존 SQL assertions는 유지하고 결과의 policyQuestion만 정상 정책 확인 메타데이터로 바꾼다. 테스트를 완화하지 않는다.
- known-gaps는 ID를 유지하여 이전 링크를 보존하고 정상 확정·문제 확인·미지원 유지·후속 보류를 구분한다.
- 초기 baseline-audit는 과거 실행 기록으로 보존하고 이번 결정 기록을 안내한다.

## Risks / Trade-offs

- 보류가 해결로 오인될 수 있음 → GAP-005 이후는 원래 근거를 남기고 보류로만 표시한다.
- 복수 조직의 전화번호 분리와 계정 연결 지원이 혼동될 수 있음 → GAP-002에 두 범위를 별도로 적는다.
