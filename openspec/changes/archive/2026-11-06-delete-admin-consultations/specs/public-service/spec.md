## ADDED Requirements

### Requirement: PUB-004 확인된 관리자 상담 삭제

시스템 SHALL NORMAL ADMIN이 자기 조직의 CONSULT_REQUEST만 명시적 확인 후 삭제할 수 있도록 한다. 상담 상세의 별도 확인 창에서 취소는 변경하지 않고 삭제 중 중복 저장/삭제를 막는다. 서버는 POST·동일 출처·정확한 ID·확인 의도·조직·종류를 검사하고 DB DELETE RLS도 동일한 조직/종류를 제한한다. 성공은 상담 목록으로 이동하고 오류나 없는 대상은 성공으로 표시하지 않는다.

삭제한 상담의 이름·전화·문의·메모와 연결된 종 알림·푸시 event/delivery는 삭제한다. 다른 상담·예약·발송 이력·푸시 구독은 유지한다. 24시간 성공 요청 키는 개인정보 원문 없이 기존 만료까지 유지하고 같은 요청의 재전송이 상담·알림을 복원하지 않게 한다. 마이그레이션 설치는 기존 데이터를 삭제하지 않는다.

#### Scenario: 삭제 확인과 취소

- **WHEN** 관리자가 상담 상세에서 삭제를 열고 취소하거나 확인한다
- **THEN** 취소는 원본을 유지하고 확인한 삭제만 처리한다. 성공하면 목록에서 사라지고 종 알림을 새로 조회한다. 저장·삭제 중 다른 저장/삭제 제출은 비활성이다.

#### Scenario: 권한과 대상 제한

- **WHEN** 익명·학생·권한 회수 관리자·타 조직 관리자 또는 잘못된 Origin/메서드/ID/확인값으로 삭제를 요청한다
- **THEN** 상담을 삭제하지 않으며 일반 알림 레코드의 삭제도 조직 관리자에게 허용하지 않는다. 기존 서비스 관리자 권한은 유지한다.

#### Scenario: 삭제와 동일 요청 재전송

- **WHEN** 자기 조직 상담을 삭제한 뒤 만료 전 동일한 성공 요청 UUID와 내용을 재전송한다
- **THEN** 상담과 연결 종·푸시 기록은 남지 않고 같은 요청으로 다시 생성하지 않는다. HMAC 해시가 다른 요청은 충돌 처리하며 다른 이력과 구독 기기는 유지한다.
