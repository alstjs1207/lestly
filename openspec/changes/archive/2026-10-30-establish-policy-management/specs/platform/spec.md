# Spec Delta

## Purpose

서버 렌더링과 라우팅, 로컬 검증, DB 변경의 운영 경계를 정의한다. 빌드 성공·테스트 통과·운영 적용을 구분하고 기존 예약 데이터와 배포 호환성을 보존한다.

## ADDED Requirements

### Requirement: PLAT-001 런타임과 비공개 디버그 경로

시스템 SHALL Node 24.x의 24.22.1 이상에서 검증·빌드·배포하고 production에서 debug 라우트를 제외한다. 루트 경로는 로그인 흐름으로 연결하며 사용하지 않는 샘플 컴포넌트의 존재를 서비스 기능으로 간주하지 않는다.

#### Scenario: 지원하지 않는 런타임

- **WHEN** Node 25로 배포 빌드 검증을 실행한다
- **THEN** 지원 런타임이 아니므로 빌드 전 검사에서 실패한다.

### Requirement: PLAT-002 SSR 스트림 종료와 취소

시스템 SHALL 서버 렌더링 요청 취소·오류·완료 때 스트림과 정리 절차를 처리하고 요청 종료 뒤 불필요한 작업이 유지되지 않게 한다.

#### Scenario: 클라이언트 요청 취소

- **WHEN** 서버 렌더링 스트림 중 요청이 취소된다
- **THEN** 렌더링을 중단하고 관련 리스너·타이머를 정리한다.

### Requirement: PLAT-003 공유 DB와 변경 보존

운영 절차 SHALL preview·운영의 DB 공유를 정상 구성으로 취급한다. 새 정책은 새 신청부터 적용하고 기존 예약을 보존한다. 실제 DB 변경은 별도 마이그레이션·백업·트랜잭션·전후 검증으로 수행하며 로컬 테스트는 격리 fixture를 사용한다.

#### Scenario: 정책 관리 체계 도입

- **WHEN** 명세·개발 도구를 도입하고 로컬 회귀를 실행한다
- **THEN** 연결된 고객 DB를 마이그레이션하거나 시험 예약을 작성하지 않는다.
