# 수강생 예약 오픈 방식

관리자 `/admin/settings`의 **예약 오픈 방식**에서 조직별로 한 가지를 선택한다.
선택한 방식의 입력만 표시하고, 현재 기준 예약 가능한 수업 날짜를 미리 보여준다.
설정 저장 전에는 실제 정책에 반영하지 않는다.

| 방식          | 설정          | 동작                                                                                                                 |
| ------------- | ------------- | -------------------------------------------------------------------------------------------------------------------- |
| 월별 오픈     | 오픈일 1~31일 | 매월 지정일 한국 시간 00시에 다음 달 예약을 연다. 해당 날짜가 없는 달은 말일에 연다.                                 |
| 오늘 기준 N일 | 0~365일       | 오늘부터 N일 뒤 날짜까지 포함하여 신청할 수 있다. 매일 한국 시간 00시에 범위가 이동한다. 0일은 오늘 수업만 허용한다. |

월별 25일이면 10월 24일에는 현재 시각 이후~10월 31일의 수업을 신청할 수 있고,
10월 25일 00시부터는 11월 30일까지 신청할 수 있다. 이번 달의 남은 수업도 계속 허용한다.
오픈일 31일을 지정하면 2월에는 28일, 윤년에는 29일 00시에 다음 달을 연다.

이동식 14일이면 10월 29일에는 11월 12일까지, 10월 30일에는 11월 13일까지 신청할 수 있다.
수업의 **시작 날짜**를 기준으로 판단한다. 허용 마지막 날에 시작해 다음 날 끝나는 수업도 기존 시간 규칙에 따라 허용한다.

예약 가능 범위 안에서도 수강 기간·접수 마감·휴무 요일·차단 시각·정원·본인 일정 중복 검사를 통과해야 한다.
범위를 줄이거나 방식을 바꿔도 이미 등록한 예약은 유지하며, 범위 밖 예약도 조회·관리할 수 있다.
관리자 직접/반복 등록은 학생 예약 기간 제한의 예외이며 기존 정원·중복·수강 기간 검증은 유지한다.
취소 정책은 기존의 전날까지 규칙을 유지한다.

## 저장과 호환성

`settings.booking_window`에 아래 중 하나만 저장한다. 설정이 없는 조직의 기본값은 월별 25일이다.
기본값을 만들기 위해 기존 설정이나 예약을 수정하지 않는다.

```json
{ "mode": "monthly", "openingDay": 25 }
```

```json
{ "mode": "rolling", "daysAhead": 14 }
```

혼합 항목·미지원 방식·누락·범위 밖·소수 값은 UI/API/DB에서 거절한다.
저장된 정책을 읽지 못하거나 잘못된 값이 있으면 임의로 기본값으로 바꾸지 않는다.

기존 `booking_policy`는 수업 길이·시각·간격·접수 마감의 6개 필드를 유지한다.
서버는 두 설정을 한 번에 읽고, 화면과 예약 API에 전달할 때 예약 기간을 합친다.
정책을 저장하면 시간 규칙·예약 기간·정원·시각 차단·요일 차단의 5개 행을 한 번의 upsert로 저장한다.
새 방식 필드가 없는 이전 폼을 제출해도 현재 저장된 예약 기간은 보존한다.

예약 기간은 같은 조직의 구성원이 읽을 수 있고 관리자만 변경할 수 있다.
DB는 설정 저장과 예약에 같은 조직 잠금을 사용하며, 잠금 이후 최신 예약 기간을 읽는다.
조회가 허용했어도 실제 예약 시점에 범위가 달라지면 DB에서 다시 거절한다.
예약 가능 시간 조회는 최신 정책을 함께 반환하며, 학생 예약 화면은 날짜·길이·한국 날짜 변경 시 다시 조회한다.

## 적용과 검증

- `sql/migrations/0034_booking_window.sql` → 새 앱 순서로 반영한다. 기존 행을 변경하는 SQL은 없다.
- SQL 검사에서는 전체 이력 재생, 기존 데이터 보존, 월말·윤년·연말·한국 자정의 JS/SQL 결과 일치,
  허용 마지막 날의 조회/저장, 다음 날 거절, 정책 축소 후 기존 예약 조회, 관리자 예외,
  권한·조직 격리 및 잘못된 기간 입력 시 설정 전체 저장의 롤백을 확인한다.
- 실행: `npm run test:unit`, `npm run test:db`, `npm run build`, `npm run test:booking-window:ssr`.
- 로컬 검증 이후 사용자의 후속 요청으로 실제 DB와 프리뷰에 반영한다. 현재 적용·배포 상태와 전체 결과는
  [공통화 계획의 Phase 4](service-generalization-plan.md#phase-4)를 따른다.
