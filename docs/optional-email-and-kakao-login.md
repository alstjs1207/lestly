# 이메일 선택 입력과 카카오 로그인

## 수강생 등록·초대

1. 관리자는 이름·전화번호 등 수강생 정보를 등록한다. 이메일은 비워도 된다.
2. 수강생 상세 화면 또는 목록에서 **초대 링크**를 연다.
3. **링크 만들기**를 누르고 **링크 복사** 또는 **카톡 안내 문구 복사**를 선택한다.
4. 관리자가 해당 수강생과의 카카오톡 대화에 직접 붙여넣어 전달한다.
5. 수강생은 링크에서 카카오로 로그인한다. 이메일 대조 없이 초대 토큰으로 기존 수강 정보와 연결된다.

링크는 7일 동안 유효하고 1회만 사용할 수 있다. 재발급하면 기존 링크는 무효가 된다. 목록과 상세 화면은 같은 초대창을 사용한다. 클립보드 사용에 실패하면 입력창의 링크를 직접 선택해 복사할 수 있다. 카카오톡 자동 발송 기능은 없다.

계정의 식별 기준은 Supabase Auth 사용자 ID와 Kakao identity다. 서비스 데이터는 안정적인 `profiles.profile_id`로 연결한다. 이메일이나 전화번호가 같다는 이유로 기존 수강생과 자동 연결하지 않는다.

## 카카오 인증 설정

앱은 Kakao의 `profile_nickname,profile_image`만 요청한다. Supabase의 `options.scopes`는 기본 scope에 **추가**되므로 이메일을 제거하지 못한다. `options.queryParams.scope`로 Kakao에 전달되는 최종 scope를 지정하며, 로그인과 기존 계정에 카카오 연결하기에 동일하게 적용한다.

운영 프로젝트에서 다음 설정을 확인해야 한다.

- Supabase → Authentication → Sign In / Providers → Kakao → **Allow users without an email** 켜기.
- Kakao Developers → 카카오 로그인 → 동의항목: `account_email`을 필수 항목으로 지정하지 않는다. 이메일을 수집하지 않는 운영이라면 사용하지 않도록 설정한다.
- `profile_nickname`, `profile_image`는 앱의 동의항목에 사용할 수 있도록 설정한다.
- Supabase Redirect URLs에 실제 서비스의 `/auth/social/complete/kakao` 콜백을 허용한다. 기존 초대의 `invite` 쿼리도 보존돼야 한다.

2026-10-21 사용자가 Supabase 설정 완료를 확인했다. 대시보드 설정값은 에이전트가 직접 조회하지 않았으며, 실제 카카오 계정의 동의·콜백 완료는 배포 후 확인한다. 로컬 브라우저에서는 최종 인가 요청의 scope가 `profile_nickname,profile_image`이고 `account_email`이 제외된 것을 확인했다.

## 다른 이메일 사용처 검토

| 사용처 | 처리·운영 방향 |
| --- | --- |
| 수강생 연락 이메일 | `profiles.contact_email`은 nullable. 미입력·공백은 `null`, 입력한 경우 형식 검증. 관리자가 수정·삭제할 수 있다. |
| 일반 로그인 | 카카오를 첫 번째 경로로 표시. 처음 이용하는 수강생은 관리자 초대 링크로 안내. |
| 기존 이메일 로그인·관리자 이메일 가입 | 기존 계정을 위해 유지. 이메일 방식 자체를 선택했을 때만 주소·인증이 필요하다. 관리자 가입까지 카카오로 전환하려면 프로필/약관/조직 생성 흐름을 별도로 확장하는 것이 좋다. |
| 이메일 없는 계정의 비밀번호 | 설정 화면에서 추가 폼을 숨기고 카카오 계정 이용 안내. 비밀번호 API와 직접 비밀번호 설정 경로에서도 이메일 없는 계정은 처리하지 않는다. |
| 이메일 추가·변경 | 관리자가 원할 때 사용하는 선택 기능. 현재 이메일이 비어 있어도 새 주소를 등록할 수 있게 기존 주소 입력란의 `required` 제거. Auth 이메일 변경은 새 주소 인증을 유지한다. |
| 프로필·사이드바 | 이메일 타입을 optional로 두고, 주소가 있을 때만 표시. |
| 결제 | 이메일이 없으면 Toss `customerEmail` 필드를 보내지 않는다. 기존 결제 데모의 운영 제한은 유지. |
| 환영 메일 | 기존 SQL 트리거가 이메일 없는 사용자는 큐에 넣지 않는다. 이메일 없이 가입해도 프로필 생성은 정상 처리. |
| 예약·취소·리마인더 메일 | 기존 알림 생성·워커가 주소가 없을 때 `SKIPPED`로 처리. 전화번호 기반 알림톡/SMS와 관리자 인앱 알림을 중심으로 운영 권장. 실제 알림톡은 채널·템플릿 승인과 발송 설정이 별도로 필요하다. |
| 문의 양식 | 답변 이메일을 선택으로 변경. 미입력 문의도 접수하고, 답변을 원하면 이메일 입력 안내. 입력된 주소의 형식 검증과 CAPTCHA는 유지. |
| OTP·매직 링크·비밀번호 찾기 | 이메일 인증 방식을 선택한 기존 계정용 경로로 유지. 이메일 없는 카카오 사용자는 카카오에서 계정을 복구한다. |
| 마케팅 이메일 | 기존 수신 동의는 선택이며 기본값은 false. 향후 발송 기능에서는 주소 유무와 수신 동의를 모두 확인해야 한다. |
| 관리자 수신 주소·메일 서비스 설정 | `ADMIN_EMAIL`, Resend 설정은 서비스가 메일을 보내기 위한 운영 설정으로, 사용자 필수 입력과는 별개다. |

Auth 이메일과 관리자 입력 연락 이메일은 별도 값이다. 인증 이메일 변경을 임의로 연락 이메일에 덮어쓰지 않는다. 일반 사용자의 연락 이메일 수정이 필요해지면 연락처 설정 기능으로 분리하는 것이 좋다.

## 검증

- 기존 DB 스키마가 nullable 이메일과 초대 토큰을 지원하므로 새 마이그레이션 없음.
- 타입 검사와 프로덕션 빌드.
- 일반/초대 카카오 요청의 최종 scope 전달, 이메일 없는 OAuth 콜백과 초대 RPC 호출, 이메일 없는 계정의 비밀번호 API 차단 회귀 테스트.
- 문의 이메일 미입력·공백·잘못된 형식·정상 주소 테스트.
- 수강생 등록 시 이메일 필드 생략·잘못된 주소 테스트.
- 격리된 PostgreSQL에서 이메일 없는 가입의 프로필 생성·환영 메일 생략, 기존 초대 연결과 테넌트 권한 회귀 검사.
- 브라우저에서 데스크톱·모바일 로그인 화면과 기존 이메일 로그인 펼치기 확인.
