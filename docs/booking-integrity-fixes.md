## 데이터 보존과 적용

마이그레이션은 `0039_booking_lifecycle_integrity.sql`이다. 기존 예약·출결·알림 행을 갱신하거나 지우지 않고 함수와 트리거만 변경한다. 예약 시작·종료, 학생, 클래스, 취소 정책, 출결 이력, 기존 반복 연결을 그대로 보존한다. 이미 부모 예약이 삭제된 연결도 원본을 바꾸지 않고 관리할 수 있게 한다.

실제 적용은 `20261030_apply_booking_lifecycle.mjs`로 수행한다. `--apply` 전에는 읽기 전용으로 전제 마이그레이션과 데이터 건수를 확인한다. 적용 시 public 데이터 전체와 함수·트리거·정책·칼럼 정의를 `.vercel/backups/`의 접근 제한 파일에 보존하고 다시 읽어 검증한다. 잠금을 획득한 한 트랜잭션에서 적용 전후 모든 public 행의 지문과 칼럼·RLS 정책을 비교하고, 동일할 때만 커밋한다.

2026년 10월 30일 실제 적용에서 예약 1,112건, 수강생 프로필 36건, 알림 575건을 포함한 모든 기존 public 데이터와 칼럼·RLS 정책이 동일했다. 부모가 이미 삭제된 반복 연결 102건도 원본을 유지했다. 잘못된 예약을 가리키는 기존 미발송 수업 안내·리마인더는 읽기 전용 추가 검사에서 0건이었다.

적용 결과는 `sql/operations/20261030_booking_lifecycle_apply.result.json`, 원본 보존 확인과 설치 상태 재조회는 같은 접두사의 postflight 결과를 따른다. 비공개 백업은 Git에 추가하지 않는다.
