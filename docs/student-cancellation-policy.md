# 수강생 예약 취소 정책

조직 설정에서 수강생의 예약 취소 기한을 하나 선택한다. 설정이 없는 조직은 기존과 같은 `전날까지`다. 한국 시간을 사용한다.

| 방식              | 설정                                 | 월요일 18시 수업 예시                    |
| ----------------- | ------------------------------------ | ---------------------------------------- |
| 전날까지          | `{"mode":"previous_day"}`            | 일요일 23:59까지. 월요일 00시부터 차단   |
| 시작 N시간 전까지 | `{"mode":"hours_before","hours":24}` | 일요일 18시까지. 그 시각은 포함          |
| 시작 전까지       | `{"mode":"hours_before","hours":0}`  | 월요일 18시 직전까지. 시작한 수업은 차단 |

시간은 0~720의 정수다. 두 방식의 필드를 섞거나 빈 값·소수·문자열 숫자를 저장할 수 없다. 관리자 설정은 기존 일정 설정과 함께 한 번에 저장하며, 오류가 나면 전체 저장을 취소한다. 업데이트 전에 열어 둔 폼에서 취소 정책 필드를 보내지 않으면 현재 저장된 값을 유지한다.

## 예약 보존

- `settings.cancellation_policy`에 조직 정책을 별도로 저장한다. 기존 `booking_policy`의 여섯 시간 필드는 그대로 유지한다.
- `schedules.cancellation_policy`는 `NOT NULL`이며 기존 예약에는 `previous_day` 기본값을 부여한다. 예약 시간·수강생·출결·메모 등 다른 값은 변경하지 않는다.
- 새 예약에는 DB 트리거가 조직의 최신 정책을 저장한다. 호출자가 임의로 전달한 정책은 사용하지 않는다. 관리자 직접 등록·반복 회차도 같은 규칙을 저장한다.
- 저장된 규칙은 관리자도 덮어쓸 수 없다. 이후 조직 정책을 바꿔도 이미 등록한 예약은 영향을 받지 않는다.
- 관리자가 수업 시간을 옮기면 그 예약의 원래 규칙을 유지하고 변경된 시작 시각을 기준으로 취소 기한을 계산한다. 취소 정책은 시각 자체가 아니라 규칙의 스냅샷이다.
- 관리자의 기존 예약 변경·취소 및 출결·수강생 상태 변경에 따른 처리 예외는 유지한다.

## 수강생 화면과 API

주간 예약 패널과 월간 목록의 예약 창에 새 예약의 정책을 표시한다. 이미 취소 기한이 지난 수업을 신청하면 직접 취소 불가 안내와 확인란을 표시하고 확인 전에는 신청할 수 없다. 날짜·시작 시각·정책을 바꾸면 확인을 초기화한다.

생성 API는 표시한 정책과 확인 여부를 전달한다. 새 RPC `book_student_schedule_with_policy`는 조직·수강생 잠금을 얻은 뒤 정책을 다시 읽는다. 정책이 바뀌거나 기한을 넘겼는데 확인하지 않은 경우 예약을 만들지 않고 재확인을 요구한다. 화면은 최신 예약 가능 정보를 다시 조회한다.

기존 RPC `book_student_schedule`은 운영 앱과의 순차 배포 호환성을 위해 유지한다. 이 경로에도 동일한 DB 정책 스냅샷과 취소 제한이 적용된다. 새 확인 절차는 새 앱의 API/RPC에 적용한다.

기존 예약 상세와 취소 API는 현재 조직 설정 대신 해당 예약에 저장된 규칙을 사용한다. DB DELETE RLS도 같은 계산을 수행해 자신의 활성 예약만 기한 내 취소하도록 한다. 계산 함수는 데이터 조회 없는 순수 함수이고, 정책 조회·검증·트리거 함수는 수강생 RPC로 노출하지 않는다.

## 검증과 배포

- 마이그레이션 `0035_cancellation_policy.sql`. 적용된 과거 마이그레이션은 수정하지 않는다.
- `npm run test:unit`, `npm run test:db`, `npm run build`, 기존 SSR 검사 5종.
- DB 검사: 한국 자정·시간 단위 경계·0시간·윤년·연말 JS/SQL 일치, 마이그레이션 보존, 스냅샷 위조·수정 차단, 조직 설정 변경 후 기존 예약 유지, 다른 수강생의 취소 차단, 관리자 예외, 정책 확인 및 동시 저장 경합.
- `sql/operations/20261030_apply_cancellation_policy.mjs`: 기본 읽기 전용 점검, `--apply`는 백업 저장·읽기 검증 후 트랜잭션 적용, `--compare-backup`은 기존 데이터 대조.
- `sql/operations/20261030_verify_cancellation_policy.mjs`: 실제 DB의 격리 검증. 모든 예약은 롤백하고, 이메일 없는 임시 인증·조직 경합 데이터는 정리한다. 실제 고객 예약 생성·취소나 알림 발송은 하지 않는다.
