# 수강생 신청 시작 시간 설정

관리자 `/admin/settings`의 **수강생 신청 가능 시간**에서 조직의 시작 시각 범위·간격으로 만든 목록을 설정한다. 기본값은 09:00~20:00·30분 간격이다. 체크된 시간만 수강생의 PC 예약 패널과 모바일 예약 창에 표시한다. 전체 허용·전체 비활성화를 제공하며 설정 저장 전에는 반영되지 않는다.

- 학원별 `settings.disabled_booking_start_times`에 `{ "value": ["12:00", "12:30"] }` 형태로 비활성 시작 시각을 보관한다. 설정이 없는 기존 학원은 기존 23개 시간이 모두 허용된다.
- 수업의 **시작 시각**만 제한한다. 예를 들어 12:00을 비활성화해도 11:30에 시작한 수업은 12:00을 지나 진행할 수 있다. 매주 휴무 요일은 별도의 [수강생 신청 차단 요일](student-booking-weekdays.md)에서 설정한다. 날짜별 휴무 설정은 포함하지 않는다.
- 전체 비활성화하면 수강생의 신규 시간 선택이 모두 사라진다. 이미 등록된 일정과 이력은 변경하지 않는다.
- 관리자는 비활성화한 시간에도 신규·반복 일정을 등록하거나 기존 일정을 수정할 수 있다. 기존 정원·시간 충돌·소속 검증은 계속 적용한다.
- 예약 가능 시간 조회가 실패하면 비활성 시간은 계속 숨기고 신규 예약을 막는다. 재조회 버튼으로 다시 확인할 수 있다. 설정 조회가 실패하면 전체 허용으로 바꾸지 않는다.
- 화면을 열어 둔 뒤 설정이 바뀌어도 실제 예약 시 DB 트리거가 최신 설정으로 검증한다. 직접 RPC를 호출해도 수강생에게 `schedule_time_disabled` 오류를 반환한다.
- 관리자 설정의 숫자 값과 시간 목록은 한 번의 upsert로 저장하여 부분 저장을 방지한다.

분 단위 예약 정책 확장은 `0032_booking_policy.sql` → `0033_booking_policy_fresh_snapshot.sql` → 새 앱 순서로 적용한다. 구현·검증 상태는 [공통화 계획의 Phase 3](service-generalization-plan.md#phase-3)을 따른다. 현재 목록에 없는 이전 차단 시각도 보존한다.

## 최초 적용 순서

1. `sql/migrations/0022_student_booking_times.sql`을 적용한다. 설정 SELECT 정책, 기존 일정 쓰기 검증과 예약 가능 시간 RPC를 확장한다. 데이터 수정이나 기존 일정 삭제는 포함하지 않는다.
2. 애플리케이션은 `preview` 브랜치에 커밋·푸시하여 Vercel preview로 배포한다. 운영 `main`에는 병합하지 않는다.
