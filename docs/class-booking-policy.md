# 클래스별 예약 시간과 정원

2026-10-30. 모든 새 예약은 활성 클래스에 연결한다. 기존 예약의 시간·출결·취소 정책은 그대로 유지한다.

| 설정                                                  | 저장·적용 위치                                       |
| ----------------------------------------------------- | ---------------------------------------------------- |
| 기본 수업 길이, 허용 수업 길이, 같은 시간대 최대 정원 | 클래스                                               |
| 새 클래스 기본 수업 길이·허용 길이·정원               | 조직 설정에서 생성할 때 한 번 복사                   |
| 첫·마지막 시작 시각, 시작 간격, 접수 마감             | 조직 공통                                            |
| 휴무 요일·차단 시작 시각·예약 오픈 기간               | 조직 공통                                            |
| 새 예약에 적용할 취소 정책                            | 조직 공통; 각 예약에 신청 당시 정책 보존             |
| 총 회차                                               | 클래스 소개용; 기존 반복 예약은 수강 종료일까지 생성 |

클래스 생성 화면에는 조직의 기본값을 채운다. 저장 후에는 클래스 자체 값으로 관리하며 조직 기본값 변경은 기존 클래스에 전파되지 않는다. 구버전 생성 요청이나 SQL에서 값을 생략해도 DB 생성 트리거가 기본값을 복사한다. 수정 요청에서 값을 생략하면 해당 클래스의 현재 값을 보존한다.

기본 수업 시간은 허용 수업 길이에 포함해야 한다. 길이는 1~1440분, 정원은 1~100명이다. 클래스 화면의 추가 허용 길이에 쉼표로 여러 길이를 넣을 수 있다. 기본 길이는 자동으로 포함한다.

정원은 같은 클래스의 실제 최대 동시 참여 인원이다. 예약은 `[시작, 종료)` 구간으로 계산하므로 한 예약의 종료와 다음 예약의 시작이 맞닿으면 자리를 재사용한다. 서로 다른 클래스의 예약은 정원을 공유하지 않는다. 한 수강생의 겹치는 수업은 클래스가 달라도 등록할 수 없다. 정원을 낮춰도 기존 예약은 지우지 않고 신규 예약·변경·결석 복원을 검사한다.

수강생 패널과 모바일 다이얼로그는 선택한 클래스의 길이를 보여준다. 조회 키는 클래스·날짜·길이를 모두 포함하며, 클래스 전환 시 길이 기본값과 시작 시간·취소 불가 확인을 초기화한다. 클래스가 없으면 관리자는 클래스 생성 안내를 받고 수강생의 신규 예약은 차단된다. 예약이 있는 클래스는 UI와 FK에서 삭제를 차단하며, 사용하지 않을 클래스는 보관한다.

## 기존 데이터 전환

`0036_class_booking_policy.sql`은 클래스 미연결 예약이 있으면 중단한다. 사용자가 지정해 연결을 완료한 64건을 포함해 현재 예약 1,112건은 모두 클래스에 연결되어 있다.

기존 클래스에는 조직 허용 길이와 기존 클래스 기본 길이의 합집합을 한 번 저장한다. 기존 명시 정원은 유지하고 비어 있는 정원은 조직 기본값을 복사한다. 예약 행·취소 스냅샷·출결·수강생·알림·조직 설정은 수정하지 않는다. 이미 저장된 예약 길이가 새 허용 목록에 없더라도 원래 길이를 보존하고 같은 클래스 안에서 그대로 이동할 수 있다. 클래스를 바꾸면 대상 클래스의 허용 길이로 검증한다.

`programs.booking_duration_minutes`에 허용 길이, `duration_minutes`에 기본 길이, `max_capacity`에 실제 정원을 저장한다. `schedules.program_id`는 NOT NULL이며 삭제는 RESTRICT다. 직접 INSERT·관리자 반복 RPC·수강생 예약 RPC·출결 복원에도 DB 검증을 적용한다. `0037_preserve_existing_class_attendance.sql`은 정원을 줄여도 이미 활성인 예약의 출석 확인을 허용하고, 복원·시간·클래스 변경은 계속 검사한다. 클래스별 활성 예약 인덱스를 추가하고 기존 조직·수강생 잠금으로 동시 신청을 직렬화한다.

## 검증과 배포

- `npm run test:unit`, `npm run test:db`, `npm run build`, SSR 6종을 실행한다.
- SQL 검증은 0035까지의 기존 회귀 106개를 먼저 실행한 뒤 0036으로 전환하고 새 정책 14개와 마이그레이션 보존 검사를 실행한다.
- 실제 DB 적용은 `sql/operations/20261030_apply_class_booking_policy.mjs`로 사전 확인 후 `--apply`한다. 출석 보존 보완은 같은 스크립트의 `--attendance-fix --apply`로 적용한다. 전체 public 데이터와 함수·정책·스키마를 비공개 백업하고 한 트랜잭션 안에서 적용 전후를 비교한다.
- `20261030_verify_class_booking_policy.mjs`는 별도 임시 조직·수강생으로 실제 RPC·정원 경합을 검사한다. 인증 시나리오는 롤백하며 동시성 검사용 행은 정리 후 전체 데이터 지문을 비교한다.
- preview 검증 단계에서는 main 병합 없이 로그인한 실제 화면을 읽기 전용으로 확인했다. 후속 운영 릴리스는 아래 기록을 따른다.
- 검증 증거: `../output/lestly-class-policy-preview-20261030/`, DB 결과: `sql/operations/20261030_class_booking_policy_*.result.json`.
