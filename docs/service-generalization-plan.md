# 소규모 수업 운영 공통화 계획

2026-10-28. 기존 예약·수강생·출결·학습 기록을 유지하며 단계별로 진행한다.

## Phase 1

- 지역은 모든 조직에서 선택 입력이며, 미입력·빈 문자열·공백은 NULL로 저장한다.
  기존 지역은 마이그레이션에서 바꾸지 않는다. 수정 화면에서 지역을 지우고 저장하면 NULL이 된다.
- 수강생 유형 `organization_members.type`은 PostgreSQL enum에서 text로 전환한다.
  표시명은 학생·성인, 내부 코드는 STUDENT·ADULT다. 계정 역할(role)과는 별개다.
- EXAMINEE와 DROPPER는 STUDENT로 통합하고 ADULT는 유지한다.
  DROPPER였던 수강생은 기존 설명을 보존하며 `[이전 유형: 재수생]`을 한 번 추가한다.
  원래 분류가 없던 소속은 임의로 분류하지 않으며, 관리자 소속의 NULL도 유지한다.
- 유형은 등록·수정 시 필수다. 기본값은 STUDENT다.
  조직별 `organization_student_types`에 기본 두 유형을 저장하고 복합 외래 키로
  타 조직 전용 유형·존재하지 않는 유형을 막는다. 새 조직에도 기본 목록을 자동 생성한다.
  이 단계의 인증된 사용자는 목록을 읽을 수만 있고, 유형 편집 UI/API는 Phase 2에서 만든다.
- 화면의 등록·수정·상세·목록 필터·일괄 등록은 같은 기본 분류 정의를 쓴다.
  과거 일괄 등록 초안과 붙여넣기의 입시생·재수생 값은 학생으로 변환하고 재수 이력은 설명에 전달한다.
- DB 저장 RPC는 구버전 호출의 EXAMINEE·DROPPER도 받아 STUDENT로 정규화한다.
  구버전 화면의 선택지까지 자동으로 호환되는 것은 아니므로 DB와 새 앱의 적용은 함께 계획한다.
- 예약·출결·수강 기간·졸업·탈퇴·초대·연락처 중복 정책은 유지한다.

## Phase 2

- 현재 분류 테이블을 확장해 표시명·순서·활성 여부·기본값을 관리한다.
- 활성 유형은 조직마다 최소 1개, 기본값은 그중 1개를 보장한다. UI와 DB 모두 검증한다.
- 사용 중인 유형은 비활성화해 신규 선택에서 제외하고 기존 학생의 값은 유지한다.
  기존 비활성 유형을 변경하지 않는 일반 정보 수정도 허용한다.
- 조직별로 조회한 목록을 등록·수정·일괄 등록·필터에 연결한다.
- 과정(취미반·자격증반) 및 수업 방식(개인·그룹)은 학생 유형에 섞지 않는다.

### 프리뷰 검증과 충돌 응답 보정

- 앱 소스 커밋 `0aca6410ec51f8982af08f674c74af764b54624f`의 Vercel Preview 배포가 성공했다.
  확인 주소는 https://lestly-git-preview-alstjs1207s-projects.vercel.app 이다.
- 실제 관리자 세션에서 유형 조회 200 및 `private, no-store`, 잘못된 설정 400,
  유형 설정 UI 저장 성공을 확인했다. 공백 정규화로 동일한 값을 저장해 조직의 설정은 유지했다.
- 실제 PostgREST 경유 충돌 요청에서 0030의 `40001`이 자동 재시도를 유발하는 문제를 발견했다.
  적용된 0030은 변경하지 않고 `0031_student_type_conflict_response`로 함수의 오류 코드를
  `PT409`로 보정했다. HTTP 409 매핑·충돌 메시지·입력 유지 동작은 그대로다.
  이후 실제 프리뷰에서 409가 156ms에 반환됨을 확인했다.
  원인 참고: [Supabase 공식 문제 설명](https://supabase.com/kb/troubleshooting/high-cpu-and-infinite-transaction-retries-when-using-custom-error-codes-in-rpc-functions).
- 보정 적용 중 모든 public 테이블 데이터와 함수 권한이 동일했다.
  DB 회귀 검사 89개를 0031까지 다시 통과했고, 충돌 SQLSTATE가 PT409인지도 검사한다.
- 실제 DB의 신규 조직 기본값, 관리자 유형 추가·변경, 잘못된 기본값·활성 목록 거절,
  지역 없는 등록, 비활성 기존 값 유지, 구버전 재수생 입력 보존, 학생·익명 권한,
  두 PostgreSQL 연결의 조직 행 잠금 등 11개 검증을 통과했다. 검증용 쓰기는 모두 롤백했다.
- 실제 신규 등록 화면의 지역 비필수·학생 기본값·학생/성인 선택지,

## Phase 3

- 수업 길이는 분 단위 복수 목록과 기본값으로 설정한다. 기본값은 목록 안에 있어야 한다.
  기존 조직의 실제 동작인 180·360·540분, 기본 180분을 유지한다.
- 시작 가능한 첫·마지막 시각과 간격을 설정한다. 기존 기본은 09:00~20:00·30분이다.
  마지막 시작 시각을 수업 종료 제한으로 해석하지 않으며 기존 자정 넘김 수업을 보존한다.
- 예약은 시작 N분 전까지 접수하도록 설정한다. 기존 기본은 추가 접수 제한 없음이다.
- 기존 요일·개별 시작 시각 차단은 신규 학생 예약에 적용하고 기존 일정은 보존한다.
- 정원은 조직 전체 기준을 유지한다. 단순히 겹치는 모든 예약을 합산하지 않고
  실제 최대 동시 인원을 계산한다. 예약 조회·저장·관리자 반복 일정·출결 복구가 같은 판정을 쓴다.
- 관리자의 학생 신청 제한 예외와 정원·학생 중복·소속·수강 기간 검증은 유지한다.
- 기존 선택지에서 제거된 길이를 표시·편집할 때 임의의 길이로 바꾸지 않는다.
- 설정 화면뿐 아니라 PC/모바일 예약, 관리자 폼, 캘린더, API, RPC·트리거를 함께 수정한다.

  첫/마지막 시작 시각은 한국 시간의 같은 날짜 안에서 순서대로 지정한다. 간격은 1~1440분,
  접수 마감은 0~43200분이며 0분은 시작 직전까지 신청 가능하다. 접수 마감 경계와 정확히 같은 시각은 허용한다.
- 설정 화면에는 **시작 시간 간격**과 시간표 미리보기를 표시한다.
  40분 수업·50분 간격이면 09:00~09:40 → 09:50~10:30 → 10:40~11:20으로 이어진다.
  매시간 분을 초기화하지 않고 첫 시작 시각부터 간격을 누적한다. 마지막 시각은 시작 가능 범위의 상한이다.
  강사별 휴식을 강제하는 기능은 이 단계에 포함하지 않는다.
- 수강생의 주간 예약 패널과 월별 예약 창, 관리자 등록·반복 등록·수정, 관리자 캘린더를 정책에 연결했다.
  캘린더는 기존 범위 밖 수업과 자정을 넘긴 수업도 표시할 수 있도록 범위를 넓힌다.
  관리자 수정 화면의 날짜는 한국 시간으로 표시하며, 목록에서 제거된 기존 길이와 시작 시각은 별도 ‘기존’ 선택지로 유지한다.
  이전 길이를 3시간 배수로 반올림하거나 기본값으로 바꾸지 않는다.
- 개별 시작 시각 차단은 HH:MM 값으로 보존한다. 시간 범위·간격 변경으로 현재 목록에서 사라진 이전 차단도 보존하며,
  해당 시각이 다시 목록에 들어오면 적용한다. 요일 차단도 기존 동작을 유지한다.
  정책·정원·시각 차단·요일 차단을 한 번의 조직 범위 upsert로 원자적으로 저장한다.
  DB 트리거는 정책과 정원·차단 값의 형식을 검증하고, 예약과 같은 조직 잠금을 사용한다.
- 신규 폼은 `duration_minutes`를 보내며 API는 현재 조직의 허용 목록을 다시 확인한다.
  기존 폼의 `duration=1/2/3`은 180/360/540분으로 해석해 호환한다. 임의의 기본값으로 대체하지 않는다.
  새 조회 RPC는 `get_student_booking_availability_minutes`다. 기존 시간 단위 RPC는 새 분 단위 RPC를 호출하는 래퍼로 유지한다.
  조회가 실패하면 예약 버튼을 막고 재조회 버튼을 제공한다. 잘못된 정책을 기본값으로 숨기지 않는다.
- 정원 판정은 예약 구간 안의 **실제 최대 동시 인원**을 사용한다. 종료와 시작이 맞닿으면 같은 자리를 함께 차지하지 않는다.
  예를 들어 09~10시 1명, 10~11시 1명은 최대 동시 1명으로 계산한다.
  JS 사전 검사, 학생 가능 시간 조회, DB 저장, 관리자 반복 일정, 출결 복구가 같은 원칙을 사용한다.
  조직·학생 잠금과 권한·수강 기간·개인 중복 검사도 유지한다.
  DB 정원·개인 중복 검사를 AFTER 트리거에서 수행해 일괄 이동 중의 이전 위치와 잘못 충돌하지 않도록 했다.
- 설정 변경은 기존 예약·출결·알림을 재작성하지 않는다. 정원을 줄인 경우에도 기존 예약은 그대로 두고 추가 신청과 출결 복구를 검증한다.
  관리자의 학생 접수 제한 예외, 월별 25일 오픈, 기존 취소 규칙은 유지한다. Phase 4·5는 진행하지 않았다.
