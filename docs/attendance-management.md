# 출결 관리

구현: `/admin/attendance` · DB migration `0027_attendance.sql`

## 운영 흐름

- 기본 날짜는 한국 시간 기준 오늘이다. 날짜를 변경하여 과거 예약도 출결 입력·정정할 수 있다.
- 예약 한 건마다 미확인(`PENDING`), 출석(`PRESENT`), 결석(`ABSENT`)을 기록한다. 하루에 여러 예약이 있으면 별개의 참여 기록이다.
- 수업 시작 후 체크할 수 있다. 결석자를 먼저 고르고, `미확인 N건 모두 출석`으로 나머지를 체크한 뒤 확인창에서 일괄 저장한다. 변경하지 않은 예약은 유지한다.
- `지난 미확인 모아보기`는 선택 날짜에 한정하지 않고 시작된 모든 미확인 예약을 오래된 순서로 찾는다. 목록은 페이지당 50건이며 일괄 체크와 상태 개수는 현재 페이지 기준이다.
- 날짜·페이지·메뉴 이동과 탭 종료 전에 저장하지 않은 변경을 확인한다. 저장 중에는 입력을 잠근다.
- 이력에서 이전/변경 상태, 처리자 이름, 실제 처리 시각을 확인할 수 있다. 수업 날짜와 출결 처리 시각은 서로 다르다.

## 예약 취소와 정정

- 결석을 저장하면 **선택한 예약만** `cancelled_at`을 기록하여 취소한다. 과거 예약도 동일하게 처리하며 원본 예약을 삭제하지 않는다. 반복 예약의 다른 회차는 유지한다.
- 취소된 예약은 일반 일정·예약 가능 시간·정원·중복 검사·홈 집계와 수업 안내 발송 대상에서 제외한다. 출결 화면과 이력에는 남는다.
- 결석을 출석 또는 미확인으로 정정하면 예약을 복구한다. 학생 시간 중복과 학원 정원을 다시 검사하여, 취소 후 다른 예약이 자리를 차지했다면 일괄 정정을 거절한다. 진행 중 결석 처리도 가능하다.
- 이미 출결을 처리한 예약은 일반 관리자 API로 이동하거나 삭제할 수 없다. 과거 출결 정정은 전용 RPC가 처리한다. 졸업·수강 종료 후에도 관리자는 기존 수업의 출결을 정정할 수 있으며 새로운 수업을 만드는 예외 권한은 주지 않는다.
- 클래스 삭제 방지는 취소된 예약을 포함한 예약 원본이 있으면 유지한다.

## 데이터와 추후 정산

- `schedules`: 출결 상태, 버전, 최근 처리자/시각, 취소 시각을 저장한다. 원래 학생·클래스·수업 시간·반복 회차 식별자를 유지한다.
- `attendance_events`: 매 변경마다 별도 이벤트를 추가한다. 학생, 클래스, 담당 강사의 ID/이름과 수업 시작·종료 시각을 스냅샷으로 보존한다. 정정 시 최초 스냅샷을 유지하므로 이후 클래스·강사 정보 변경이 이력을 바꾸지 않는다.
- 출석으로 확인하고 종료된 수업만 학습 시간, 월별 참여 횟수, 배움 기록, 히트맵, 연속 학습 집계에 포함한다. 진행 중인 수업은 종료 후 반영한다.
- 기존 과거 예약도 자동 출석 전환하지 않는다. 모두 미확인으로 남으며, 새 preview 앱은 `get_student_attended_hours`로 출석 확인 기준을 사용하므로 출결 입력 전에는 합계가 줄어들 수 있다. 기존 운영 앱의 `get_student_completed_hours`는 종료 예약 기준을 유지하여 preview 도입만으로 운영 합계가 초기화되지 않게 한다. 결석 취소는 양쪽 집계에서 제외한다. 원본 시간 정보는 삭제하지 않는다.
- 금액·단가·차감·정산 기간 확정은 이번 기능에 포함하지 않는다. 향후 정산에는 수업 건별 상태와 스냅샷, 정정 이력을 사용한다.

## 원자성·권한

- `save_attendance(org, changes)` 하나의 트랜잭션으로 최대 200건을 저장한다. 학원/학생 advisory lock과 예약 행 잠금, 입력별 버전 검사를 사용한다. 변경된 결과가 같은 재시도는 추가 이력 없이 성공한다. 다른 결과의 오래된 버전, 삭제·타 학원 예약, 미래 수업, 복구 충돌이 있으면 전체를 롤백한다.
- HTTP action은 POST·동일 출처·관리자 권한을 검사하고 32 KiB 이하 JSON만 받는다. 학원 ID는 요청 본문 대신 인증된 관리자 정보에서 가져온다.
- 출결 칼럼은 브라우저 직접 쓰기를 막는다. 이벤트는 관리자에게 자기 학원 조회만 허용하며 인증 클라이언트의 생성·수정·삭제 권한을 주지 않는다. RPC 임시 플래그만 위조해도 직접 변경할 수 없다.
- 원본 예약 정정과 출결 정정의 동시 실행도 버전 및 행 잠금으로 보호한다. 여러 DB 연결의 실제 경합/전송은 별도 환경 검증 대상이다.

## 검증과 적용

- `npm run test:unit`: 날짜/입력 제한, 참여 집계, 날짜·전체 미확인 조회 범위, 인증된 학원 범위, API 오류·요청 크기 검증.
- `npm run build` 후 `npm run test:attendance:ssr`: 실제 빌드된 라우트를 StaticRouter로 렌더링하여 서버에서 loaderData와 명단이 전달되는지 확인한다. 화면을 별도 컴포넌트로 분리할 때 라우트 파일에는 로컬 default 컴포넌트를 두어 React Router의 props 주입 변환이 적용되게 한다.
- `npm run test:db`: 격리된 PGlite에서 전체 migration 재실행과 권한·원자성·취소·정정·동일 결과 재시도·충돌 회귀 검사. 공용 DB에 연결하지 않는다.
- 로컬 예시 데이터로 실제 출결 컴포넌트의 일괄 저장, 사후 정정, 이력, 미저장 이동 방지와 모바일 배치를 확인한다. 실제 계정/예약은 수정하지 않는다.
- 배포 시 migration을 먼저 적용하고 앱을 배포해야 한다. 새 칼럼이 없는 DB에 새 앱만 배포하지 않는다. `database.types.ts`에는 이 migration에 대응하는 타입을 추가했다. 공용 DB의 자동 타입 생성으로 덮어쓰려면 migration 적용 후 수행한다.
- 소스맵 업로드 자격 증명 없는 로컬 빌드에서는 Sentry 업로드를 비활성화하여 앱 빌드만 검사한다.
