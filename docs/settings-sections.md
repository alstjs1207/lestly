# 설정 영역별 저장

2026-10-30. 설정 화면을 클래스 생성 기본값, 공통 예약 규칙, 수강생 관리로 구분한다. 상단 바로가기로 필요한 영역에 이동할 수 있고 각 카드에서 독립적으로 저장한다.

| 영역                  | 저장하는 값                                                 | 버튼                |
| --------------------- | ----------------------------------------------------------- | ------------------- |
| 새 클래스 기본값      | 허용 수업 길이·기본 길이·기본 정원                          | 클래스 기본값 저장  |
| 예약 가능한 기간      | 월별 오픈일 또는 오늘 기준 예약 일수                        | 예약 기간 저장      |
| 예약 시간과 접수 마감 | 첫·마지막 시작 시각, 시작 간격, 접수 마감, 시각별 신청 허용 | 예약 시간 저장      |
| 휴무 요일             | 수강생 신규 예약 차단 요일                                  | 휴무 요일 저장      |
| 예약 취소 기한        | 전날까지 또는 시작 N시간 전                                 | 취소 기한 저장      |
| 수강생 유형           | 분류명·사용 여부·순서·기본 분류                             | 기존 유형 설정 저장 |

각 영역에 적용 범위와 저장 결과를 표시한다. 저장 중인 카드만 잠그며 다른 카드의 작업은 계속할 수 있다. 다른 카드의 잘못 입력한 초안은 현재 카드 저장을 막지 않는다. 저장 후에도 다른 카드의 미저장 입력을 유지한다. 실패 안내는 해당 카드에만 표시하고 입력을 보존한다. 저장 후 페이지 이동 없이 해당 영역에서 결과를 확인할 수 있다.

## 저장과 데이터 보존

새 요청은 `/api/admin/settings`에 `section`과 해당 카드의 입력만 전송한다. 서버는 선택한 영역만 검증하고 로그인한 관리자의 조직 ID로 `save_booking_settings_section` RPC를 호출한다. 알 수 없는 영역이나 필수 필드 누락은 전체 저장으로 처리하지 않고 400으로 거절한다.

클래스 기본값과 공통 시간 규칙은 기존 `settings.booking_policy` JSON 행을 공유한다. RPC는 예약과 같은 조직 잠금을 얻은 뒤 최신 JSON을 읽고 해당 영역의 필드만 합친다. 서로 다른 영역을 동시에 저장해도 앞선 영역의 저장값을 덮어쓰지 않는다. 정원과 기본 길이, 공통 시간과 차단 시각은 각각 같은 트랜잭션으로 저장해 부분 반영을 방지한다. 휴무·기간·취소 정책은 자신의 행만 갱신한다. 기존에 열어 둔 통합 폼의 저장 방식도 호환된다.

학생·다른 조직 관리자·익명 사용자는 RPC로 설정을 바꿀 수 없다. 기존 RLS, 예약 검증 함수, 클래스 생성 기본값 복사, 예약별 취소 스냅샷은 유지한다. 설정을 변경해도 기존 클래스와 예약을 다시 작성하지 않는다.

## 검증과 배포

- `0038_settings_section_saves.sql`은 저장 RPC와 실행 권한만 추가한다. 마이그레이션 자체는 설정·클래스·예약을 수정하지 않는다.
- `20261030_apply_settings_sections.mjs`는 사전 확인, 비공개 백업, 적용 전후 데이터·기존 함수·정책 비교를 수행한다. `--apply`로 적용하고 인자 없이 사후 확인한다.
- SQL 회귀는 기존 120개와 영역 저장 11개를 실행한다. 단위 테스트는 각 폼의 입력 범위, 잘못된 요청 차단, 조직 ID 고정, 로컬 응답과 오류 처리를 검사한다.
- `20261030_verify_settings_sections.mjs`는 임시 조직에서 실제 권한·영역별 보존 11개와 두 방향의 동시 저장 경합을 검증한다. 인증 테스트는 롤백하며 경합용 데이터는 정리 후 전체 데이터 지문을 비교한다.
- 실제 컴포넌트로 저장 중 다른 영역 조작, 성공·실패·재시도, 잘못된 다른 초안 보존, 모바일 폭과 영역별 전송 필드를 확인한다. 배포한 preview에서는 실제 운영 설정을 바꾸지 않고 화면과 폼 구성을 읽기 전용으로 확인한다.
- 기록은 `../output/lestly-settings-sections-preview-20261030/`와 `sql/operations/20261030_settings_sections_*.result.json`에 보관한다. 원본 프로젝트에서 작업하며 별도 worktree·clone은 만들지 않는다.

## 모바일 설정 화면 전환

2026-10-30. 768px 미만에서는 상단의 6개 메뉴를 탭으로 표시하고 선택한 설정 영역 하나만 보여준다. 메뉴를 누를 때 앵커로 하단에 이동하지 않으며 URL의 해시도 바꾸지 않는다. 기본 화면은 클래스 기본값이다. 데스크톱은 기존 전체 보기와 바로가기를 유지한다.

탭 내용은 `forceMount`로 유지하고 CSS로 표시 여부만 바꾼다. 탭 전환 시 미저장 입력·오류·저장 결과를 버리지 않고, 저장 중 다른 탭으로 이동해도 요청이 계속된다. 응답이나 재조회가 현재 탭을 바꾸지 않는다. 화면 폭을 바꿔도 같은 폼과 선택 상태를 유지한다. 기존 영역별 저장 API와 DB 구현은 변경하지 않는다.
