# 운영 보안 수정과 배포

2026-10-22 보안 검토에서 확인한 권한·예약·알림·Storage·의존성 문제를 수정했다. 공개 상담은 사용자 결정에 따라 **일시 중단**한다. CAPTCHA나 rate limit 없이 상담을 다시 활성화하지 않는다.

## 수정 내용

- `0016`: 관리자 임의 멤버십 연결과 식별자 변조, 익명 상담 직접 INSERT를 차단한다. 조직 FK와 일정 유효 시간·수강생 상태 검사를 설치하고 기존 무결성 검사 후 제약을 VALIDATE한다. 초대 대상 프로필 잠금과 함수 실행 권한도 반영한다.
- `0019`: 자기 프로필은 이름·아바타·마케팅 동의만 직접 수정할 수 있다. 관리자 관리 수강 기간·연락처·지역·식별자는 보호한다. 관리자는 소속 수강생의 관리 필드를 수정할 수 있고, 기존 서버 RPC도 유지한다.
- 학생 예약은 `book_student_schedule` RPC로 저장한다. 학생 직접 INSERT 정책은 회수한다. DB 트리거는 관리자·서버 쓰기에도 조직별/학생별 트랜잭션 잠금, 상태·프로그램 조직·시간 범위·중복·정원을 검사한다. 학생에는 추가로 KST 등록 월·시간대·3/6/9시간·수강 기간을 검사한다. 기존 이력은 변경하지 않는다.
- 공개 상담 API는 DB 접근 전에 503을 반환하고 화면 버튼도 비활성화한다. DB anon INSERT는 별도로 차단한다.
- 알림톡 함수는 gateway JWT 외에 서비스 전용 Bearer 인증을 검사한다. 앱에 설정한 서버 키가 자동 생성 Edge 키와 다를 수 있어 `ALIMTALK_WORKER_SECRET`을 명시적으로 설정할 수 있다. 키를 교체하면 앱과 함수의 worker 설정을 함께 갱신해야 한다. 공개 키·일반 사용자 JWT·인증 없는 요청은 발송 처리에 도달할 수 없다.
- `0020`: 커버/강사 이미지의 인증 사용자 직접 쓰기 정책을 제거한다. 업로드는 관리자·조직 검증과 실제 이미지 서명 검사를 통과한 서버 경로만 사용한다. 신규 경로에 조직 UUID를 포함하고 기존 이미지 URL은 유지한다. 버킷 MIME은 PNG/JPEG/WebP/GIF로 좁힌다.
- 스크립트에는 nonce CSP를 적용한다. 법률 문서는 빌드 시 컴파일하며 브라우저 동적 코드 평가와 런타임 MDX 컴파일을 제거한다. 업로드 성공 여부와 관계없이 공개 client sourcemap을 빌드 끝에 삭제한다.

## 의존성

사용하지 않는 `react-email` CLI·파일/HTTP i18n backend·런타임 MDX bundler를 운영 의존성에서 제거하고, Supabase CLI를 개발 의존성으로 옮겼다. ORM·Supabase SDK/SSR·Sentry·메일 컴포넌트·Vite 및 간접 의존성을 보안 버전으로 갱신했다. 별도 이메일 프로젝트의 패키지와 lockfile도 업데이트했다.

`braces@3.0.3`의 GHSA-vfj7-8cjw-p6xm은 upstream 패치 버전이 없다. `scripts/harden-braces.mjs`가 설치 시 알려진 원본 해시/버전을 확인하고, 재귀 처리 전에 중첩을 64단계로 제한한다. 버전이나 원본이 달라지면 설치를 실패시켜 재검토하도록 한다. 실제 설치본에 대한 정상 패턴/공격 패턴 회귀 테스트를 포함했다. npm registry 감사에는 이 패키지와 상위 의존성 경고가 계속 표시되며, 이를 0건이라고 보고하지 않는다. upstream 패치가 나오면 로컬 보호 패치를 제거하고 업데이트한다.

## 적용 절차와 증거

전체 코드·SQL 검증 후 아래 순서로 운영에 적용한다. `db:migrate`로 수동 적용 이력을 건너뛰지 않는다.

1. `node sql/operations/20261022_apply_security.mjs prepare`: 0016 적용, 수동 적용한 0017·0018 재검증/원장 정리, 0019의 보호 트리거와 예약 RPC 설치. 이전 앱을 위해 학생 INSERT 정책과 기존 Storage 쓰기는 이 단계에서 유지한다. 학생 직접 요청도 새 DB 업무 규칙 검사를 받는다.
2. preview에 커밋·푸시하고 검증한 뒤 main에 병합·푸시한다. Vercel 배포 성공과 운영 새 앱을 확인한다.
3. `node sql/operations/20261022_apply_security.mjs finalize`: 학생 직접 INSERT 정책 회수, 0020 적용, 최종 원장 반영. 정책·함수·제약·버킷을 다시 조회한다.

작업 스크립트는 학생·소속·수업의 전체 행 해시와 건수가 전후 동일해야 DB 변경을 커밋한다. `sql/operations/20261022_security_*.result.json`에 비밀값 없는 결과를 보존한다.

검증:

- 단위 테스트: 자기 프로필·권한·worker 인증·상담 중단·설치 의존성 패치 및 기존 회귀 검사.
- DB 검사: 전체 마이그레이션 재생, 학생/관리자/anon 권한, 예약 RPC와 직접 쓰기 우회 차단, 정원·수강 기간·Storage 정책.
- `sql/checks/security-concurrency.mjs --live`: 별도 임시 조직에서 두 PostgreSQL 트랜잭션의 잠금 대기와 정원 초과 거부를 확인한다. 연락처·Auth 계정은 만들지 않고 모든 알림 템플릿을 끄며, 테스트 행은 정리한다.
- 타입 검사, 깨끗한 `npm ci`, 운영 빌드, 알려진 비공개 환경값의 client build 부재, client `.map` 부재, 실제 HTTP nonce 일치/상담 503을 확인한다.
- 실제 메시지·결제 발송은 하지 않는다. 알림톡 인증은 발송할 수 없는 `notification_id: 0`으로 확인한다.

Vercel prebuild 단계는 배포 환경의 실제 키로 알림 ID 0 인증 검사를 실행한다. 공개 키 401·서버 키 400이 아니면 배포를 실패시킨다. 키나 지문을 브라우저 페이지로 전달하지 않는다.
